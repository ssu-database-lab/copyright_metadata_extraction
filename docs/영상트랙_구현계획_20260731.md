## 3. 키프레임 추출 설계

### 3-1. 방식 선정 — 왜 장면전환 검출을 단독으로 쓰지 않는가

| 방식 | 70분 영화 12장 | 짧은 수어클립 | 결함 |
|---|---|---|---|
| (a) 균등 `fps` 필터 | 26.9초 | 0.19초 | 전체 디코딩 → 길이에 비례해 비용 폭증 |
| (b) 장면전환 `select=gt(scene,0.4)` | 41.7초(전량) | **0장 — 완전 실패** | 아래 2가지 치명적 결함 |
| (d) 첫/중간/끝 고정 | 0.2초 | 0.1초 | 첫 프레임 pblack=100(암전) 실측 |
| **(e) 균등 시크 + thumbnail (채택)** | **0.97초** | 0.7초 | 없음 |

**장면전환 검출의 실측 결함 2가지**

1. **단일샷 영상에서 0장 반환** — 수어 클립(2.4초 고정 카메라)에서 0 프레임. **데이터의 73%가 이 유형**이므로 단독 사용 시 3/4에서 실패.
2. **`-frames:v N` 조합 시 시간적 편향** — 70분 영화에서 추출된 12장이 전부 **첫 6분 구간**에 몰림(ffmpeg이 N장을 채우는 즉시 종료). 실제 컷 257개는 70분에 고루 분포. 균등 커버리지를 얻으려면 전량 검출(41.7초) 후 재선별하는 2-pass가 필요 → **하이브리드 대비 43배 비쌈**.

### 3-2. 채택 방식 — 균등 앵커 + 국소 대표 선별

```bash
# 앵커 1개당 1회 호출 (앵커 = 전체 구간 균등 분할점)
ffmpeg -hide_banner -loglevel error -nostdin \
  -ss "$T" -t 2 -i "$VIDEO" \
  -vf "thumbnail=n=30,scale=768:768:force_original_aspect_ratio=decrease" \
  -frames:v 1 -q:v 3 -y "frame_%02d.jpg"
```

**핵심 3가지**
- **`-ss`를 `-i` 앞에** 배치 → input seek(키프레임 점프). 뒤에 두면 순차 디코딩으로 수십 배 느려짐
- `-t 2`로 2초 창만 디코딩 → `thumbnail=n=30`이 그 안에서 히스토그램 기준 최적 1장 선택 (흐릿한/전환 중간 프레임 회피)
- `scale=768:768:force_original_aspect_ratio=decrease` → 세로/가로 영상 모두 **긴 변 768 상한**

> ⚠️ **`-vsync`는 ffmpeg 6.1에서 deprecated.** 웹 예제 대부분이 `-vsync vfr`을 쓰지만 **`-fps_mode vfr`** 로 작성할 것.

### 3-3. 길이별 프레임 수

연구 근거: Qwen3-VL 계열은 **8프레임에서 최적**, 16 이상은 이득 없음. 8→32 구간에서 향상되다 32 이후 정체. 우리 과업은 VQA가 아니라 **메타데이터 추출**이므로 벤치마크보다 적은 프레임으로 충분.

| 길이 | 해당 데이터 | 목표 N | 오버샘플 | 근거 |
|---|---|---|---|---|
| **< 10초** | ccl 수어 1,003건 (73%) | **3** | 5 | 단일 고정샷. 실측 8장 중 2장 중복 |
| 10~60초 | donated 일부 | **5** | 9 | |
| 1~5분 | donated 장편 | **8** | 14 | VLM 최적점 |
| 5~15분 | 소수 | **12** | 21 | |
| **15분+** | expired 499건 (27%) | **16** | 28 | 정체점 이전 |

**하한 2장 강제** — 정적 영상에서 중복제거가 1장까지 줄이는 사례 실측됨.

### 3-4. 품질 필터링 (실측 임계값)

| 필터 | 임계값 | 실측 근거 |
|---|---|---|
| **암전 프레임 제거** | `pblack >= 95` | 페이드인 t=0~1.5초 = 100, 끝 크레딧 = 97~100. ⚠️ **실제 야간 씬이 pblack=60** 이므로 평균 휘도 기준은 위험(콘텐츠를 버림) |
| **중복 제거** | dHash(8×8) 해밍거리 **> 6** | 70분 영화 12장 → 12/12 유지(오탐 0) · 수어 8장 → 6/8(rest pose 중복 제거) · 야간 고정샷 5장 → 2장 |
| **페이드/저대비** | `YMAX - YMIN < 20` | |

> `blackdetect` 전체 스캔은 70분 영상에 113초 — **사전 패스로 쓰지 말 것**. 추출된 JPEG 12장만 사후 검사하면 약 1초.
> `mpdecimate`는 추출된 스틸에 대해 변별력 없음(12/12 통과) → **dHash 사용**.

**구조**: 목표의 **1.75배 오버샘플 → 품질필터 → farthest-point(max-min) 다양성 선별 → N장**

실측 효과: 105초 영상의 꼬리 암전으로 7장만 남던 것이 **정상 8장 확보**

```
13002255_....mp4  dur=104.8s  target=8  sampled=14  passedQC=13  final=8   2.81s  335KB
test_long.wmv     dur=4241s   target=16 sampled=28  passedQC=28  final=16  1.93s  419KB
```

### 4-3. 권고 ~~(초판: Gemma 1순위)~~ → **2026-08-03 대체**

**모델 체인 확정:**

```

2순위  qwen3-vl-235b-a22b-instruct    80.8% · 4.0초 · ₩1.51  (OCR용으로 이미 보유)
```

- **1순위 근거** — 정확도 1위이면서 상위권 중 유일하게 빠르다. 출력토큰이 629로 가장 적어(2위 3,162, 3위 5,271) 지연·비용이 동시에 낮다. 추론형 모델의 긴 사고 토큰은 **정확도로 이어지지 않았다**.
- **2순위 근거** — 정확도 4위지만 **전체 최속(4.0초)**이며 OCR 단계에서 이미 검증되어 신규 의존성이 없다.
- **Gemma 강등** — 영상에서 omni-plus보다 덜 정확하고 4배 느리다. 다만 토큰이 가장 적고(프레임당 280 고정) **이미지 트랙에서는 계속 사용**하므로 최종 폴백으로 남긴다.
- **비용은 판단 기준이 아니다** — Gemma→omni-plus 증가분은 영상 1건당 **₩1.74**로 건당 총원가 ₩96의 1.8%에 불과하다. 비용은 통합검증(₩35.4)이 지배한다.

**초판 권고와의 관계** — 4-1의 "Qwen 비디오모드 토큰 4.4배 절감" 판단은 여전히 유효하나, 위 시험은 전 모델을 **프레임(다중이미지) 방식으로 동일 조건 비교**한 것이다. 네이티브 비디오모드 전환은 별건으로, 비용이 아닌 **타임스탬프 그라운딩 품질** 관점에서만 검토한다.

**⚠️ 단서** — 표본이 영상 5건·26항목으로 작고 1·2위 격차가 2항목이다. 또한 §3 프레임 결함이 남은 상태의 측정이므로, 결함 수정 후 15~20건으로 재확인이 필요하다(비교보고서 §7-2).

## 5. 음성(ASR) 트랙 — 1차 구현 제외 (실측 근거)

### 5-1. 데이터에 음성이 사실상 없다 (전수 2,209건)

| 버킷 | 오디오 스트림 有 | **실제 가청**(peak > −40dB) | 디지털 무음(< −60dB) | 자막 |
|---|---|---|---|---|
| ccl (수어) | 100.0% | **0.6%** | 99.4% | 0 |
| donated | 80.9% | 39.0% | 57.0% | 0 |
| expired | 98.6% | 94.7% | 5.3% | 0 |
| **전체** | **93.6%** | **33.4%** | **65.7%** | **0 (0.0%)** |

- **"오디오 스트림 93.6%"는 함정** — 그중 2/3가 −91dB 디지털 무음(인코딩 시 붙은 빈 트랙)
- 가청 오디오 429시간 중 **99.8%가 1895~1962년 외국(영어) 만료 영화**
- **한국어 & 가청 = 191파일 / 0.88시간 = 전체 452.5시간의 0.19%**
- **자막 트랙 0건** (내장·사이드카 모두) → ASR 없이 텍스트를 얻을 우회로 없음

### 5-2. ⚠️ ASR 환각이 실측으로 확인됐다

한국어 가청 191건에 whisper base 실행 → 한글 0자 52.9%, 잡음 1~9자 36.6%, 유의미 10자↑ 10.5%.
**large-v3로 재검증했더니 더 유창하고 더 위험한 환각을 생성했다:**

| 실제 영상 | large-v3 출력 |
|---|---|
| 지하철 앰비언트 | "안녕하세요 여러분 오늘은 **제주도**에서 가장 유명한 곳인 **부산**의 한 대중교통역입니다…" |
| 신촌 창천교회 외관 | "안녕하세요 여러분! 오늘은 **제주도**에서 가장 유명한 곳인 **부산**의…" |
| 흐린 날의 하늘 | "오늘은 이곳에 있는 한가한 한가한 한가한…" |

무관한 3개 영상에 **동일한 날조 문장**이 붙었고 문장 내부도 모순(제주도↔부산). 이를 `설명`/`키워드`에 넣으면 **신촌 교회 영상이 "부산 대중교통역"으로 등록**된다.
**통합검증은 LLM↔NER 교차검증이므로, 음성에서만 온 환각은 대조군이 없어 걸러지지 않는다.**

> 대조 확인: 완전 디지털 무음 30건은 **0/30 환각**. 위험한 것은 **앰비언트 노이즈**이고, 그것이 우리 한국어 가청 클립의 다수 모드다.

### 5-3. 대신 지금 넣을 것 — ffprobe 게이트 (비용 0)

키프레임 추출에 ffprobe는 어차피 호출한다. 같은 호출에서 **음성유무·자막유무**를 기술 메타데이터로 수집·저장해 두면, 향후 ASR 도입 시 재작업이 없다.

```bash
# 스트림 유무
ffprobe -v quiet -print_format json -show_format -show_streams "$F"
# 실제 가청 여부 (무음 트랙 배제) — 30초 표본
ffmpeg -v info -nostats -t 30 -i "$F" -map 0:a:0 -af volumedetect -f null -
#   → max_volume < -40dB 이면 사실상 무음
```

> **참고**: 정지화면+음악 영상(예: "음악 모음집 8곡")은 키프레임으로 내용을 알 수 없으나, **ASR로도 해결되지 않는다**(음성이 아니라 음악). 이런 경우 `고유장면 ≤2` 플래그를 결과에 남겨 "시각 정보 부족"을 명시하는 것이 정직하다.

## 6. 기술 메타데이터 (ffprobe)

### 6-1. 가용성 및 정확도 (60건 프로빙 + 공유마당 정답 15건 교차검증)

| ffprobe 경로 | 가용 | 매핑 | 검증 |
|---|---|---|---|
| `streams[v].width/height` | 60/60 | 화질 `"W x H"` | **15/15 일치** |
| `format.duration` | 57/60 | 재생시간 | **15/15 일치** |
| `streams[v].r_frame_rate` | 60/60 | fps | |
| `streams[v].codec_name` | 60/60 | 코덱 | |
| `streams[a]` 존재 | 57유/3무 | 음성유무 | |
| `format.tags` | 57/60 | 제목·연도·키워드 보너스 | |
| `streams[v].display_aspect_ratio` | **49/60** | ⚠️ **사용 금지** | **2건 불일치** |

### 6-2. ⚠️ 화면비율은 `display_aspect_ratio`를 쓰지 말 것

640×480인데 `5:4`, `15:11`을 반환하는 사례 발생(비정방형 SAR 태그). **width/height의 gcd 축약이 15/15 일치**:

```python
g = math.gcd(w, h); aspect = f"{w//g}:{h//g}"
# 852x480 → "71:40" (공유마당 표기와 동일), 1920x1080 → "16:9"
```
공유마당 표기 규약이 표준 DAR가 아니라 **저장비 축약**이기 때문.

### 6-3. 기타 주의

- **`.swf` 125건(6%)은 `format.duration`이 None** — flv1+mp3 스트림은 잡히나 duration 없음. 폴백(`-count_frames`) 또는 null 허용
- `format.tags`에서 무료 메타 획득 — 예: `WM/Category: "1890년대;영상;단편영화;역사;공포;흑백영화;무성영화..."` → **keyword 시드**, `title`, `WM/Year` → `created_date`
- **공식 등록 기준에는 영상 기술메타 요구가 없다** (공공저작물 메타데이터 요소 58행에 duration/resolution 없음; KCISA 운영DB의 영상 5,010행은 `디지털화 형태` 100% 빈값). → ffprobe 자동추출은 **규정 준수가 아니라 "빈 칸을 무료로 채우는 순증 가치"** 로 포지셔닝
- **KOGL 등록은 썸네일 2종 필수** (목록 294×220 / 상세 720×400) → **우리가 뽑는 대표 프레임을 규격 리사이즈하면 등록요건 충족** (부수 효과)

### 7-3. 프롬프트 설계 요점

프레임이 **개별 이미지가 아니라 한 영상의 시간순 대표 프레임**임을 명시해야 한다. 타임스탬프 라벨을 함께 제공.

> "다음 N장은 하나의 영상에서 시간순으로 추출한 대표 프레임입니다(각 프레임의 시점: 0초, 18초, 36초…). 개별 이미지가 아니라 **영상 전체**를 설명하세요."

출력 스키마는 이미지용을 확장: 기존 8필드 + `duration_desc`(전개 양상), `scene_count`(장면 전환 정도), `video_type`(다큐/광고/애니/기록 등)

## 8. ⚠️ 운영상 최대 경고 — `/mnt/e` I/O 병목

동일 99MB 1080p 파일, 동일 8회 시크:

| 위치 | 소요 |
|---|---|
| `/mnt/e` (외장 드라이브) | **16.5초** |
| WSL 네이티브 디스크 | **1.46초** |

**11배 차이.** `/mnt/e` 읽기 처리량 실측 **약 4.7MB/s**. CPU가 아니라 디스크가 병목이므로 **병렬도를 높여도 개선되지 않는다.**

- 2,000건 배치 시 `/mnt/e` 직독으로 평균 0.83초/건 → 약 30분 (감내 가능)
- 대용량 파일(expired 300~500MB)이 많으므로 **병렬화 시 I/O 경합 주의**
- **처리 대상은 네이티브 경로(`/home/mbmk92/...`)로 복사 후 처리 권장**
