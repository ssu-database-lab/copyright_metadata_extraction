## 4. 수집 방법

### 4-1. 접근 방식

**익명 HTTP (로그인·API키 불필요)** — 브라우저 UI의 검색 흐름과 동일한 GET 요청임을 Playwright로 검증(12개 셀 전부 파라미터·총건수 일치).

```
① 목록  GET /gongu/wrt/wrtCl/listWrt{Image,Video,Text}.do?menuNo=..&pageIndex=p&pageUnit=100&licenseCd=..
        → 정규식 view.do?wrtSn=(\d+) 추출, 중복 제거
② 상세  GET /gongu/wrt/wrt/view.do?wrtSn=N&menuNo=M
        → <dl><dt>라벨</dt><dd>값</dd> 파싱 (제목·저작권자·출처·이용조건·요약정보·원문제공)
③ 게이트 원문제공이 '원문파일명 …' → HOSTED(다운로드) / '원문URL' → EXTERNAL(사유 기록 후 스킵)
④ 다운로드 GET /gongu/wrt/cmmn/wrtFileDownload.do?wrtSn=N&fileSn=k  (k=1..N, soft-404까지 반복)
```

### 4-2. 층화 샘플링 (대표성 확보)

첫 페이지부터 연속 수집하면 소수 업로더 배치에 편중되므로, **총건수 범위에 분산된 복수 시작페이지**에서 라운드로빈 수집했습니다.
예: 이미지/CCL은 pageIndex 1 · 700 · 1,400 · 2,100 · 2,800

### 4-3. 구현 시 반영한 기술적 특성 (전부 실측 확인)

| 항목 | 내용 |
|---|---|
| gzip | 서버가 JPEG·MP4까지 gzip 전송 → 자동 해제 필요 |
| 파일명 | Content-Disposition이 %-인코딩 또는 raw UTF-8(latin-1 mojibake) 2가지 → 양쪽 폴백 처리 |
| soft-404 | 없는 파일도 **HTTP 200** + 60바이트 `<script>alert('File Not Found[N]')` → 본문 검사로 판정(상태코드 신뢰 불가) |
| Content-Length 없음 | chunked 전송 → 사전 크기 확인 불가, 스트리밍 저장 필수 |
| 이어받기 불가 | Accept-Ranges 없음(Range 무시) → `.part` 기록 후 완료 시 rename |
| 대용량 | 영상 평균 433 MB(최대 7.8 GB) → 컨테이너 헤더(ASF/MP4/MKV/SWF)로 사전 크기 산출 후 상한 적용 |
| 멀티파일 | 작품당 최대 4파일(미리보기 PNG + master ZIP 혼재). 어문 hwp/txt는 byte-identical 사례 존재 → sha1 중복 제거 |

### 4-4. 서버 부하 대응

- 동시성 2~4 워커, 요청 간 0.5초 지연
- **영상/만료 수집 중 8시간 경과 후 서버가 HTTP 503 반환** → 230건 실패
- 지수 백오프(5→10→20→60초) 적용 후 1워커·1.5초 지연으로 재시도 → **229/230 복구** (270 → 499건)

### `gongu_index.xlsx` 컬럼

### 상태·사유 분류 체계

| status | 의미 |
|---|---|
| `ok` | 다운로드 완료 |
| `external` | 원문이 외부 호스팅 → 파일 없음 (issue: `external_no_file`) |
| `filtered` | 조건 미달로 제외 (issue: `desc_too_short`, `excluded_title`) |
| `skipped_existing` | 재개 시 기존 파일 확인 |
| `failed` | 실패 (issue: `http_error`, `timeout`, `conn_error`, `write_error`, `no_file_soft404`, `size_exceeded`, `truncated`, `duplicate_sha1`) |
