## 1. 통합 검증 개요

통합 검증(Consolidation)은 **LLM 메타데이터 추출**과 **NER 엔티티 추출** 결과를 비교·분석하여 최종 메타데이터를 결정하는 후처리 단계입니다.

### 처리 흐름

```
LLM 추출 결과 (구조화된 메타데이터)
        ↓
    ┌───────────┐
    │ 통합 검증  │ ← Qwen3-Next-80B (LLM이 "전문가 심판" 역할 수행)
    │ (LLM 판정) │
    └───────────┘
        ↑
NER 추출 결과 (개체명: 인명, 기관명, 주소, 전화번호 등)
        ↓
    최종 메타데이터 + 필드별 판정 근거
```

**통합 검증 모델:** Qwen3-Next-80B-A3B-Instruct (Alibaba Cloud DashScope API)

> **LLM 단독 수행 여부:** 통합 검증은 LLM(Qwen3-Next-80B)이 단독으로 수행합니다. LLM이 두 결과(LLM 추출 + NER 추출)를 입력받아 필드별로 비교·판정하고, 충돌 시 어느 쪽을 채택할지 결정합니다. 별도의 규칙 기반 로직이 아니라 LLM의 언어 이해 능력을 활용한 판정입니다.

## 2. 판정 유형 설명

통합 검증은 각 메타데이터 필드에 대해 아래 5가지 판정 유형 중 하나를 부여합니다.

| 판정 유형 | 의미 | 상세 설명 | 신뢰도 범위 |
|-----------|------|----------|------------|
| **AGREED** | 일치 | LLM과 NER이 동일한 값을 추출한 경우. 두 독립적인 모델이 같은 결과를 도출했으므로 **가장 높은 신뢰도**를 부여합니다. | 0.9 ~ 1.0 |
| **CONFLICT** | 충돌 → 판정 | LLM과 NER이 서로 다른 값을 추출한 경우. **통합 검증 LLM이 문맥을 분석하여** 더 정확한 값을 선택하고 그 근거를 제시합니다. 예: NER이 기관명의 일부만 인식한 경우 LLM의 전체 기관명을 채택. | 0.7 ~ 0.9 |
| **LLM_ONLY** | LLM 단독 추출 | **LLM만 해당 필드를 추출**하고 NER에서는 대응되는 엔티티가 없는 경우. 동의 유형, 계약 조건 등 NER로는 추출이 불가능한 구조적·의미적 정보가 이에 해당합니다. NER의 교차 검증이 없으므로 AGREED보다 낮은 신뢰도를 부여합니다. | 0.5 ~ 0.7 |
| **NER_ONLY** | NER 단독 추출 | **NER만 해당 엔티티를 추출**하고 LLM 스키마에 대응 필드가 없는 경우. LLM이 놓친 인명, 연락처 등을 NER이 보완하는 역할을 합니다. | 0.5 ~ 0.7 |
| **MISSING** | 미추출 | LLM과 NER 모두 해당 필드를 추출하지 못한 경우. 문서에 해당 정보가 존재하지 않거나, 두 모델 모두 인식에 실패한 것입니다. | 0.0 |

### 3.4 통합 검증의 효과

본 문서 처리 사례에서 통합 검증의 주요 개선 효과:

1. **기관명 정확도 향상**: NER이 "지식정보"로 부분 인식한 기관명을 LLM의 "주) 나라지식정보"로 보정
2. **주소 정확도 향상**: NER이 주소 경계를 잘못 잡은 2건(주소에 "전화번호" 포함, 호수 누락)을 LLM 결과로 보정
3. **역할 구분 정확도**: NER이 제3자 제공 기관(한국문화정보원)을 처리자로 오인식한 것을 문맥 기반으로 정정
