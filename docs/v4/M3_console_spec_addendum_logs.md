User request: the 실행 로그 must show everything about model loading, API calls and processing — starting with the NER model load failure, which is currently invisible (NER only `print()`s it in debug mode, then silently falls back to regex; the console run log captures only the `web.pipeline` logger). Do NOT fix the NER loading bug itself (the user wants to see the failure first).

## A. Backend (`api/module/ner/ner_system.py`, `api/web/pipeline.py`, `api/web/console_api.py`, small logging additions in `api/module/ocr/*`, `api/module/llm_extraction/*`, `api/module/consolidator/*`, `api/module/clip_extraction/*`)

1. **Everything through `logging`, Korean messages, a component tag.** Line format in `out/test.log`: `HH:MM:SS LEVEL [set_id] [구성요소] 메시지`, 구성요소 ∈ `시스템 · 업로드 · 문맥 · OCR · LLM · NER · 통합 · VLM · API · 측정 · 채점`. SSE `log` events add `level`, `component`, `set_id`.
2. **NER (`ner_system.py`)**: log at INFO model load start (model name, path, device), load success (seconds, labels), cache hits (DEBUG); at **ERROR the load failure** (exception class and first line, model path, and a one-line Korean explanation), then WARNING per call `모델 미적재 — 정규표현식 대체` with entity counts (model vs regex). Replace the debug-only prints on these paths with logger calls (prints may stay only for the CLI download helper). `ner_predict` results gain `mode` (`model` | `regex_fallback`), `model_loaded` (bool), `load_error` (str|None), `entity_count`. Outputs otherwise unchanged.
3. **Pipeline (`pipeline.py`)**: response gains `ner_mode`, `ner_model_loaded`, `ner_load_error`, `ner_entity_count`. One log line per stage with what was used: upload (name, size), router (modality), contract context parse (title/종별 found or not), OCR (provider, model, text layer vs OCR, pages, fallback model/provider used, seconds), LLM extraction (model, seconds, token usage if available, retries), NER (mode, model, entities), consolidation (model, fallback used, degraded and reason, counts AGREED/CONFLICT/LLM_ONLY/NER_ONLY/MISSING, seconds), VLM (backend chain, pings, selected backend, each failure with reason and the fallback taken, frames extracted with timestamps, JSON parse failures), file measurements (format, size, resolution, SHA-256 seconds), licensee rule result. Propagate the set binding into the pipeline's internal worker threads (e.g. `contextvars.copy_context().run` on executor submits) so nested-thread records are attributed to the right set.
4. **Console capture (`console_api.py`)**: attach the run handler (INFO) to the loggers `web`, `module`, `api` and `httpx` (each HTTP call: method, host, path, status — scrub query strings and anything that looks like a key) and `openai` (retries), attributing records to the run and set via the set binding; records without a set are written as `[-]`. Never write secrets.
5. **System log (server-wide)**: a ring-buffer handler (last 5,000 records) on the same loggers plus `uvicorn.error`, installed at app start. `GET /api/test/syslog?after=<seq>&level=&component=&q=` → `{"items":[{"seq","ts","level","component","logger","run_id","set_id","message"}],"last_seq"}` (login required). Startup, model cache loads, service pings and errors outside runs appear here.
6. **Consolidation details** in `GET /api/test/runs/{id}/sets/{set_id}`: add `"consolidation": {"available": bool, "legs": [<leg>]}` with one `<leg>` per pipeline leg that ran consolidation (T-001: contract; T-002: work leg only when 저작물 통합 was on — otherwise `available: false` with `reason`), `<leg>` = `{"leg": "contract"|"work", "model_used", "requested_model", "fallback_used", "degraded", "degraded_reason", "status", "seconds", "summary": {"total_fields","agreed_fields","conflicted_fields","llm_only_fields","ner_only_fields","missing_fields","overall_confidence"}, "decisions": [{"field","label_ko","key23"|null,"llm_value","ner_value","final_value","decision","confidence","reasoning"}], "validation_errors": [...], "fields_before", "fields_after", "lost_fields": [...], "ner": {"mode","model","loaded","load_error","entity_count","entities":[{"text","type"}]}}` read from the leg's `consolidated_metadata.json` (`validation_report.decisions`, `summary`, `ner_entities`, model fields) and `llm_metadata.json`. `label_ko` from the unified schema descriptions where available; `key23` maps unified fields to the 23 keys (author→creator, copyright_holder/licensee party→copyright_holder, reproduction_right…, valid_period→contract_validity_period, etc.).

## D. Secret scrubbing (mandatory)
Google AI Studio (Gemma) puts the API key in the URL query (`?key=…`); OpenAI-style clients send `Authorization: Bearer`. Every captured line (test.log, SSE, syslog) passes `scrub_secret()`: drop query strings from logged URLs, mask `sk-…`, `sk-ws-…`, `AIza…`, `AQ.…`, `Bearer …`, `key=…`, `api_key=…`, and any value of an env var whose name contains KEY/SECRET/TOKEN/PASSWORD. Raising library logger levels for capture must not flood the uvicorn stdout/journal (filter on the root handlers or capture without propagation).
