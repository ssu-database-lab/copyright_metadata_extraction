### 추가 슬라이드 A — 멀티모달 AI 속성정보 추출 (과제 4.1)

**제목: 현재 연구 진행 내용 ① — 멀티모달(이미지·영상) 속성정보 추출 기술**

**1. 모델 비교실험 → 하이브리드 아키텍처 확정**
- CLIP 계열(제로샷 분류) vs 생성형 VLM 비교실험 수행(KOGL 실데이터)
  - CLIP 계열: **유사도·중복판별에 특화**(진짜쌍 유사도 ≈0.98 vs 비관련 ≈0.45) — 중복탐지(FAISS)용으로 활용
  - 속성정보(설명·유형·키워드) 추출은 **생성형 VLM이 우수** → 매체 기준 저작물 유형 분류 가능
- **VLM 삼중화(폴백체인): Gemma 4 31B @OpenRouter(API, 주) → Gemma 4 31B @자체서버(폴백) → Qwen3-VL-235B @DashScope(예비)** — 동일 모델을 API 우선·자체서버 폴백으로 이중 확보, 이종 모델까지 3단 안전망. 기존 OCR/LLM 폴백 체계와 동일 구조로 장애 시 자동 전환 (실동작 검증 완료)

**2. 실서비스 파이프라인 통합 완료**
- 업로드 파일 **모달리티 자동 라우팅**: 문서→OCR·LLM·NER 경로 / 이미지→VLM 경로 (API·웹UI 반영, 데모 가능)
- VLM 추출 결과를 통합 스키마(67필드)로 매핑 → 기존 통합(consolidation) 단계에 그대로 연결

**3. 모델별 성능 비교 실험 결과 (설명·유형·키워드 추출)**

*(표 1) 속성정보 추출 — CLIP 제로샷 vs 생성형 VLM (KOGL 실데이터)*

| 모델 | 저작물 유형 판단 | 설명(description) | 키워드(keyword) | 처리 성능 | 판정 |
|---|---|---|---|---|---|
| multilingual-CLIP (제로샷 분류) | **top-1 50%** — 피사체 기준으로 분류해 매체(사진/미술/도형) 구분 실패 | 생성 불가 | 생성 불가 | 0.43s/건 | 속성추출 **부적합** |
| **Gemma 4 31B (주모델)** | Qwen과 **일치 86%**(50건)·매체 기준 분류 성공 | 자연스러운 한국어, **이미지 내 문자 판독 우수**(간판 "WANDO"/"66TH" 정확) | 평균 ~7개, 환각 미관찰, 241 tokens | 7.3s/건, 파싱 100% | **속성추출 주모델** |
| Qwen3-VL-235B (예비) | 문서 스캔류(어문) 매체 판단은 더 정확 | 장면 묘사 상세하나 **외국문자 혼입 사례**(테ント 등) | **환각 사례 존재**(무관 키워드 '드론사진'), 279 tokens | 6.0s/건, 파싱 100% | 폴백(예비) |

- 8건→15건→**50건**으로 확대 검증: 두 VLM 모두 JSON 파싱 100%, 유형 일치 60→86%(다양셋→일반셋). 불일치는 로고(미술 vs 도형)·문서스캔(사진 vs 어문) 등 경계 사례에 집중 → 통합(consolidation) 단계에서 조정 가능
- **설명·키워드의 정답 대비 정량 정확도**: 매니페스트 태그(#결혼식 등 범주형)로는 채점 불가 판정 → **골드셋 100건**(설명 3점척도·키워드 정밀도 0~1·유형 정답) 구축 완료, 라벨링 후 산출 → **성능지표(멀티모달 정확도 80%) 공식 측정 기반**

*(표 2) 유사도·중복판별 — 임베딩 모델 3종 (80건 × 4 변형 = 320 질의)*

| 모델 | 중복검출 rank-1 | 진짜쌍 유사도 | 비관련 유사도 | 마진 | 속도 |
|---|---|---|---|---|---|
| SigLIP 2 (so400m) | 64.7% | 0.971 | 0.539 | 0.432 | 0.116s/건 |
| KoCLIP (ViT-L14) | 65.0% | 0.968 | 0.549 | 0.419 | 0.028s/건 |
| multilingual-CLIP | 64.7% | 0.973 | 0.535 | 0.438 | **0.015s/건** |

- 리사이즈·JPEG압축·크롭·밝기 변형에도 rank-1 동일 수준(강건) / ~65% 상한은 **KOGL 썸네일이 서로 다른 ID로 바이트 동일 중복 제공되는 데이터 특성**(SHA256 검증) — 확보한 풀해상도 원본 기준 재평가 예정
- 진짜쌍(0.97) vs 비관련(0.54)의 명확한 분리 → **FAISS 임계값 0.85~0.90로 중복판별 서비스 구성 가능** (무하유 중복판별 연계 후보)

### 추가 슬라이드 B — 텍스트 권리정보 추출·통합 (과제 4.1↔4.2 연계)

- **학습데이터 구성방식 연구**(EEECS 논문 ①): 답만(M1)/문맥포함(M2)/네거티브추가(M3) × 3개 인코더(KLUE-BERT·mBERT·KoELECTRA) 교차실험
  - 실문서 평가에서 **M1 붕괴(0.44~0.50) vs M2 최고(0.869~0.872)** — 인코더와 무관하게 재현
  - → **"정답 주변 문맥까지 라벨링해야 한다"는 학습데이터 설계 지침** 도출(저자원 한국어 IE 일반 지침)

**2. 통합 파이프라인 End-to-End 실증 (EEECS 논문 ②)**
- 합성 계약서 100건(정답셋 보유)을 실제 배포 파이프라인(OCR→LLM∥NER→통합)으로 처리, 100/100 성공

- 필드별 **출처 판정(AGREED 31.2%·신뢰도 0.96 / CONFLICT / LLM_ONLY / NER_ONLY / MISSING) + 신뢰도 + 한국어 근거** 제공 → 단일모델이 못 주는 신뢰성 확보
- 처리 성능: 중위 115초/문서(OCR 33s·LLM 17s·NER 18s·통합 55s, LLM·NER 병렬로 ~16s 절감)
