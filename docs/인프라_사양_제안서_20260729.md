## 요약 (3줄)

1. **현행 구성(상용 API 활용)은 GPU 없이 4 vCPU / RAM 16GB 로 충분합니다.** 지금 운영 중인 서버 실측값이 근거입니다(4 vCPU / 31GB / GPU 없음, API 프로세스 실사용 1.12GB). 월 운영비 약 **₩34,000**.
2. **전부 자체 호스팅(GPU 도입)은 "같은 시스템의 이전"이 아니라 모델 등급 하향을 의미합니다.** 현행 OCR·추출 모델은 GPU 4~8장이 필요해 실증 예산 밖이며, 소형 모델 대체 시 정확도 손실이 발생할 수 있습니다(미검증). 초기투자 1,170~1,810만원 + 구축 4~8주.
3. **권고: 하이브리드** — NER만 자체(상용 대체 불가), 나머지는 API. 단 **OCR·LLM을 국내 벤더로 1순위 재정렬**하면 비용은 동일하면서 개인정보 국외이전 리스크를 제거할 수 있습니다.

## 🔴 강력 권고: LLM은 자체 서버 구축이 아닌 **상용 API를 사용해야 합니다**

실증 환경에서 LLM을 자체 호스팅하는 것은 **권장하지 않습니다.** 근거는 다음과 같습니다.

| 근거 | 내용 |
|---|---|
| **1. 현행 모델은 물리적으로 자체 호스팅이 불가능** | OCR 모델(235B)은 **VRAM 470GB**, 추출 모델(122B)은 **244GB**가 필요합니다. **H100 GPU 4~8장(2억원 이상)** 이 있어야 하며 실증 예산 밖입니다. |
| **2. 최고급 GPU 2장(1억원 상당)으로도 부족** | RTX PRO 6000 96GB **2장(192GB)** 을 사도 현행 3개 모델 동시 운용은 **194GB가 필요해 불가능**합니다. |
| **3. 자체 호스팅 = 성능 하향 확정** | GPU를 사도 모델을 **1/7 크기로 교체**(235B→32B)해야 하며, 현재 검증된 **OCR 정확도 98%**를 유지할 수 있을지 **검증되지 않았습니다.** |
| **4. 비용 회수 불가** | 하드웨어 1,810만원 ÷ API 월 3.4만원 = **손익분기 약 44년**. GPU 2장 구성은 **122년**입니다. |
| **5. 구축 기간·부대 요건** | GPU 도입 시 **4~8주** 소요 + 공인 IP 확보(교내망 인바운드 차단 → 별도 신청) + 전용 전력 회로 + UPS + 상시 관리 인력이 필요합니다. |
| **6. 이미 검증 완료** | API 방식은 **현재 무중단 운영 중**입니다. 자체 호스팅은 처음부터 재구축·재검증해야 합니다. |
| **7. 보안 문제도 API로 해결 가능** | 개인정보 국외이전이 우려된다면 **국내 벤더(Upstage·네이버 CLOVA)로 전환**하면 됩니다. 비용은 **월 ₩32,000으로 오히려 더 저렴**하여, 추가 비용 없이 리스크를 제거할 수 있습니다. |

### 결론

> **LLM·OCR·VLM은 상용 API를 사용하고, NER만 자체 구축하십시오.**
> 이 구성은 **GPU가 전혀 필요 없으며**, 초기 투자 0원, 월 ₩34,000으로 운영되고, 이미 실운영으로 검증되었습니다.
>
> **자체 GPU 도입은 수요기관이 "완전 폐쇄망(망분리) 처리"를 계약 요건으로 명시하는 경우에만 검토할 사안이며**, 그 외의 어떤 근거(비용 절감·성능 향상·처리 속도)로도 정당화되지 않습니다.

## 3. 시나리오 A — 전부 자체 호스팅

### 3-1. ⚠️ 대전제 — 현행 모델은 자체 호스팅이 불가능합니다

| 현행 모델 | 파라미터 | BF16 VRAM | 필요 GPU | 판정 |
|---|---|---|---|---|
| Qwen3-VL-235B (①OCR) | 235B MoE | **~470 GB** | H100 80GB **×8** | ❌ GPU만 $200k+ (월 클라우드 $14,400) |
| qwen3.5-122b-a10b (②④) | 122B MoE | **~244 GB** | H100 **×4** | ❌ 비현실적 |
| Gemma 4 31B (⑤) | 31B | 61 GB (INT4 18.7GB) | 48GB 1장 | ✅ 가능 |
| KLUE-RoBERTa (③) | 0.35B | 1.3 GB | CPU | ✅ 현행 유지 |

> **MoE의 함정:** 활성 파라미터가 22B/10B라도 **전체 가중치가 VRAM에 상주**해야 합니다.

**→ 자체 호스팅 시 모델 교체가 필수이며, 정확도 손실 리스크가 따릅니다.**

| 단계 | 현행 → 대체 | VRAM | 리스크 |
|---|---|---|---|
| ① OCR | 235B → **Qwen3-VL-8B-FP8** | 9 GB | ⚠️ 정확도 재검증 필요 (한국어 OCR 오픈모델 1위) |
| ①보조 | → **PaddleOCR-VL 0.9B** | 2 GB | 한국어 MDPBench **86.0** (Gemini-3-pro 74.8 상회) |
| ②④ | 122B → **Qwen3-32B-FP8** 또는 **EXAONE 4.0 32B**(LG, 한국어 특화) | 33 GB | ⚠️ **67필드 추출 정확도 손실 — 최대 리스크** |
| ③ NER | **변경 없음** | CPU | 없음 |
| ⑤ VLM | Gemma 4 31B **유지** | 18.7 GB (INT4) | 낮음 |

> 🚨 **중요: Gemma는 OCR을 대체할 수 없습니다.**
> 한국어 OCR 벤치마크(KO-OCRAG)에서 **Gemma-3-27B = 3.63점, Gemma-3-12B = 0.50점**으로 사실상 실패 수준입니다(Qwen3-VL-8B 56.26). Gemma는 **이미지 속성·캡션 전용**으로 역할을 고정해야 합니다. 현행 아키텍처(OCR=Qwen, 이미지속성=Gemma)가 옳았음이 확인되었습니다.

- **현재는 GPU 구매 시점으로 불리합니다** — 메모리 대란으로 RTX 5090이 MSRP의 2.7배, RTX PRO 6000이 +55% 수준입니다.

### 3-2-1. 상위 구성 검토 — RTX PRO 6000 Blackwell 96GB 1장 / 2장

"현행 모델을 그대로 자체 호스팅할 수 있는가"를 판단하기 위해 96GB급 구성을 별도 계산했습니다.

**모델별 정밀도 요구량**

| 모델 | 파라미터 | BF16 | FP8 | NVFP4 |
|---|---|---|---|---|
| Qwen3-VL-235B-A22B (현행 OCR) | 235B | 470 GB | 235 GB | **118 GB** |
| qwen3.5-122b-a10b (현행 추출·통합) | 122B | 244 GB | 122 GB | **61 GB** |
| Gemma 4 31B (현행 이미지 VLM) | 31B | 62 GB | 31 GB | **16 GB** |
| Qwen3-VL-32B (OCR 대안) | 32B | 64 GB | 32 GB | 16 GB |
| Qwen3-VL-8B (OCR 경량) | 8B | 16 GB | 8 GB | 4 GB |

**① 1장 구성 (96 GB)**

| 조합 | 합계 | KV 여유 | 판정 |
|---|---|---|---|
| 현행 OCR 235B (어떤 정밀도든) | ≥118 GB | 음수 | ❌ **불가 — 카드를 바꿔도 해결 안 됨** |
| 현행 추출 122B (NVFP4) | 61 GB | 35 GB | ✅ 가능 |
| OCR 8B FP8 + 추출 32B FP8 + VLM FP4 | 58 GB | 38 GB | ✅ **1장 권장 구성** |

**② 2장 구성 (192 GB)**

| 조합 | 합계 | KV 여유 | 판정 |
|---|---|---|---|
| **현행 3종 전부 (235B+122B+31B, 전부 NVFP4)** | **194 GB** | **−2 GB** | ❌ **2GB 차이로 실패** |
| OCR 32B FP8 + 추출 122B FP8 + VLM FP8 | 185 GB | 7 GB | ⚠️ KV캐시 부족 |
| **OCR 32B FP8 + 추출 122B FP4 + VLM FP4** | **108 GB** | **84 GB** | ✅ **2장 권장 구성** |
| 현행 235B OCR(FP4) + VLM FP4 (추출은 스왑) | 133 GB | 59 GB | ✅ 가능하나 비권장(아래) |

> **핵심 결론:** 2장(192GB)으로도 **현행 3종 동시 상주는 불가능**합니다(194GB, 2GB 초과). 셋 중 하나는 교체하거나 스왑해야 합니다.

**③ NVLink 부재에 따른 배치 전략 (중요)**

RTX PRO 6000 Blackwell은 **NVLink를 지원하지 않습니다**(구매 전 재확인 필요). 따라서:

- **모델 1개가 96GB를 초과하면** 2장에 걸친 텐서병렬(TP=2)이 강제되고, GPU 간 통신이 **PCIe 5.0(~64GB/s)** 로 발생합니다. NVLink(900GB/s+) 대비 병목이 크며, **MoE는 전문가 라우팅으로 통신량이 많아 처리량 손실이 큽니다.** → 현행 235B(118GB) 운용 시 해당.
- **모든 모델을 61GB 이하로 맞추면** 각 모델을 한 장에 통째로 올려 **GPU 간 통신 0**으로 최대 속도를 냅니다.

```
2장 권장 배치 (TP 불필요)
  GPU 0 │ qwen3.5-122b (FP4) 61GB               → KV 여유 35GB
  GPU 1 │ Qwen3-VL-32B (FP8) 32GB + Gemma (FP4) 16GB = 48GB → KV 여유 48GB
```

**④ 비용·전력**

| 구성 | GPU 비용 | 시스템 포함 | GPU 전력 | 손익분기(API 대비) |
|---|---|---|---|---|
| RTX PRO 6000 96GB ×1 | 2,116만원 | 약 3,160만원 | 600W (Max-Q 300W) | 약 77년 |
| **RTX PRO 6000 96GB ×2** | **4,232만원** | **약 5,000만원** | **1,200W (Max-Q 600W)** | **약 122년** |

- 2장 구성은 PSU 1600~2000W와 전용 회로가 필요합니다. 연구실 상주 시 **Max-Q(300W×2) 버전을 강력 권장**합니다.
- ⚠️ **MoE 양자화 리스크**: 현행 주력 2종(235B-A22B, 122B-A10B)이 **모두 MoE**이며, MoE는 INT4/FP4 양자화에 민감합니다. FP4 압축 후 현재 실측 OCR 문자정확도(98%)·67필드 추출 정확도가 유지되는지는 **검증되지 않았습니다.**

**⑤ 판단**

- 데모 규모(동시 1~5명)에서 2장은 **연산력이 아니라 VRAM 용량만을 위한 지출**입니다. 처리량은 1장으로도 충분합니다.
- **2장이 필요한 유일한 이유는 현행 122B 추출 모델을 FP4로 지키고 싶을 때**입니다.
- 조사 결과 한국어 OCR은 대형 모델이 유리하지 않으므로(Qwen3-VL-**8B** 56.26 > Qwen2.5-VL-**32B** 33.36, PaddleOCR-VL **0.9B** 86.0), **235B 사수를 위한 2장 구성은 권장하지 않습니다.**
- 5,000만원을 정당화하는 근거는 여전히 **폐쇄망 요건**이지 성능·비용이 아닙니다.

### GPU 도입을 재검토할 조건 (아래 중 하나라도 성립 시)
1. 수요기관이 **완전 폐쇄망(망분리)** 처리를 계약 요건으로 명시
2. 상시 대량 배치(월 10만 건 이상) 확정 → 손익분기 약 15개월로 단축
3. 자체 모델 파인튜닝이 논문 핵심 기여로 확정

→ 이 경우 GPU 선택은 **요구 수준에 따라 3단계**입니다 (상세 계산은 §3-2-1):

| 목적 | 권장 GPU | 비용(시스템 포함) | 운용 가능 모델 |
|---|---|---|---|
| **표준 (권장)** | RTX 6000 Ada 48GB ×1 | 약 1,810만원 | OCR(PaddleOCR-VL/8B) + LLM(32B) + VLM(Gemma INT4) 동시 상주 |
| 상위 | RTX PRO 6000 96GB ×1 | 약 3,160만원 | 위 + **현행 122B 추출모델(FP4 61GB)** 유지 가능 |
| 최상위 | RTX PRO 6000 96GB ×2 | 약 5,000만원 | 위를 여유롭게(KV 84GB). **단 현행 3종 동시 상주는 여전히 불가(194GB)** |

> **주의:** 2장을 사도 **현행 OCR 235B + 추출 122B + VLM을 동시에 올릴 수는 없습니다**(194GB > 192GB). 어떤 구성이든 **OCR 모델 교체와 정확도 재검증은 불가피**합니다.
