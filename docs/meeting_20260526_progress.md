## 2. 1단계 성과 — 20개 요소 정렬 (이슈 해결)

- **이슈(무하유 왕일 프로 피드백):** 계약서/동의서 처리 시 계약서 전용 구조(`rights_holder`, `granted_rights`, `user` 등)로 출력 → 요청하신 **20개 통합 요소와 매핑 불일치**.
- **조치:** 모든 문서유형(계약서·동의서·양도동의서·공공저작물 자유이용허락 등)이 **통합 스키마(20요소)** 로 출력되도록 추출기 일원화.
- **검증:** 운영서버 반영 후 실제 양도계약서로 재테스트 → **20개 요소 정상 추출·매핑 확인.**

---

## 3. 프로젝트 변동사항 — 2단계 기술 방향 (중요)

- **CLIP 계열은 '유형 분류'에 부적합함을 실증:** 매체(사진/영상)가 아니라 **피사체(건물·공연 등)** 기준으로 분류 → 정확도 약 50%. (예: 건물 '사진'을 '건축저작물'로 오분류)
- **→ 생성형 VLM으로 전환:** "매체(medium) 기준으로 분류하라"는 지시만으로 문제 해결.
- **CLIP/SigLIP은 유사도·중복검출(FAISS) 용도로 유지** — 임베딩 기반 유사도가 본래 강점.
- **하이브리드 구조 확정:**
  - 이미지/오디오/영상 → **VLM(Gemma)** : 설명·유형·키워드
  - 이미지 → **SigLIP 임베딩 + FAISS** : 유사도·중복검출
  - 텍스트/계약서 → **OCR + LLM + NER** : 권리정보(저작권자·권리·유효기간)

---

## 4. VLM 모델 비교 — Gemma 4 31B vs Qwen3-VL-235B

- 동일 이미지·동일 프롬프트(JSON 출력)로 직접 비교.
- 두 모델 모두: 유형 6/8 일치, **풍부한 한국어 설명**, **이미지 내 텍스트 OCR**, **AI 생성물 탐지**까지 수행.
- **Gemma 우위:** OCR 정확도(예: "WANDO"·"66TH" 정확 인식, Qwen은 "ANO"·"60th" 오독), 언어 혼입 없음, **로컬 구동(비용·데이터 보안)**, Apache-2.0.
- **잠정 결론:** **Gemma 4 31B = 운영 / Qwen3-VL = 폴백.** (대규모 평가셋으로 최종 확정 예정)

---

## 5. 유사도·중복검출 — 임베딩 모델 벤치마크

- 근접 복제(리사이즈·재압축·크롭·밝기) 재현 → 원본 검색 정확도(rank-1)로 측정. (중복검출 KPI 89→92% 대응)
- **예비 결과:** SigLIP 2 = **100%**, KoCLIP = **100%** (소규모·동일유형 8건 기준; 대규모 다양 데이터로 변별 예정).
- 둘 다 FAISS 중복검출에 적합 — 최종 선정은 다양한 KOGL 평가셋에서.

## 6. KOGL 데이터 분석 (무하유 전달분 143,946건 × 75항목)

- **구성:** 이미지 7.7만(54%) · 어문 3.3만 · 오디오 2.7만 · 영상 5천 · 3D 1.5천 · 글꼴 0.5천.
- **1단계용 카탈로그 메타데이터는 충실(~100%)** (제목·분류·소장기관·해시태그·게시글URL 등) → **자동 생성 가능.**
- **2단계 권리정보는 '전부 또는 전무':** 약 **7.4만건만 완성**, 약 7만건 공백. 그리고 **기관별로 완성 여부가 갈림.**
  - 완성(~100%): 한국문화예술교육진흥원·세종학당재단·한국학중앙연구원·진주시·광진구 등
  - 공백(0%): 제주특별자치도·국가유산청·국립국악원·**한국문화정보원(자체)**·인천·부산 등
- **학습 가능 라벨 확인:** 상업적이용허락(가능/금지/불가), 보호/만료저작물. **평가셋 이미지 약 2.9만건**(유형 라벨 포함).

## 7. 이슈 및 데이터 요청 (← 핵심 협의 사항)

> 장세영 연구원님 취합 요청에 대한 회신. 별도 요청서(`data_request_to_kcisa`) 정리본 공유 가능.

1. **원본 저작물 파일 샘플** — 멀티모달 분석 + 식별자(SHA256/UCI) 생성용. (URL·경로는 있으나 파일 접근 필요)
2. **권리정보 공백 기관의 「권리정보_完」 파일** — 2단계 학습·검증 범위 확대.
3. **완성 기관의 원본 계약서·동의서** — "계약서 → 권리정보" 변환 정답쌍(가장 유용).
4. **분류표(대/중/소분류 코드표)** — 코드 해석용.
5. **권리정보 입력 기준/규칙 확인** — 자동화 로직 기준 정의.
