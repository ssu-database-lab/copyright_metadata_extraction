# 2단계 멀티모달 모델 실험 결과 보고

**과제:** AI 기반 공유저작물 분석 및 유형 판단 시스템 (문체부/콘진원 R&D) — 숭실대학교
**범위:** 2단계 이미지·텍스트 멀티모달 분석 — 모델 선정 실험
**작성:** 2026-05-29 · **실험 데이터:** 공공누리(KOGL) 실제 저작물 이미지 8건 (모두 사진저작물 유형)

---

## 0. 한 줄 요약

> **CLIP 계열은 '유형 분류'에 부적합(약 50%)함을 실증하고, 생성형 VLM으로 전환하여 문제를 해결.**
> **속성 추출 = VLM(Gemma/Qwen), 유사도·중복검출 = 임베딩(SigLIP/CLIP)**의 **하이브리드 구조**로 방향 확정.

---

## 1. 배경 및 실험 목적

- 2단계 목표: 이미지·텍스트 공유저작물에서 **속성정보(유형·설명·키워드)** 자동 추출 + **유사도·중복검출**.
- 과제계획서는 **CLIP 기반 멀티모달**을 명시 → 먼저 CLIP의 적합성을 실증적으로 검증.
- 3개 실험 수행:
  1. **실험 A** — CLIP 제로샷 유형 분류 적합성
  2. **실험 B** — 생성형 VLM 속성 추출 비교 (Gemma 4 vs Qwen3-VL)
  3. **실험 C** — 임베딩 모델 중복검출(FAISS) 성능 비교

---

## 2. 실험 A — CLIP 제로샷 유형 분류 (적합성 검증)

**방법:** multilingual-CLIP으로 KOGL 이미지 8건을 10개 저작물 유형 라벨(사진/영상/어문/미술/건축/도형…)에 대해 제로샷 분류. 한국어 라벨, 가설 템플릿(hypothesis template) 적용/미적용 비교.

**결과: 정확도 50% (4/8)** — 템플릿 적용 후에도 동일 50%.


| 이미지              | 정답    | CLIP 예측   | 정오  |
| ---------------- | ----- | --------- | --- |
| 국물떡볶이            | 사진저작물 | 사진저작물     | ✓   |
| 제주 감귤            | 사진저작물 | 사진저작물     | ✓   |
| 재두루미             | 사진저작물 | 사진저작물     | ✓   |
| 한국민속예술제          | 사진저작물 | 사진저작물     | ✓   |
| 완도 해조류센터         | 사진저작물 | **건축저작물** | ✗   |
| 엑스포 부스           | 사진저작물 | **건축저작물** | ✗   |
| 2월 문화가 있는 날(포스터) | 사진저작물 | **연극저작물** | ✗   |
| 참다래'해금'          | 사진저작물 | **도형저작물** | ✗   |


**핵심 발견 (원인 분석):**

- CLIP은 **'매체(medium)'가 아니라 '피사체(subject)'** 기준으로 분류한다.
- 예: 건물을 **카메라로 촬영한 사진** → CLIP은 피사체가 건물이므로 "건축저작물"로 오분류. 그러나 저작권법상 매체는 "사진저작물".
- 이는 CLIP의 구조적 한계 — **임베딩 유사도 모델**이라 정해진 라벨과의 시각적 유사도만 측정. 가설 템플릿으로도 개선 불가(50%→50%).

**→ 결론: CLIP은 유형 '분류'에 부적합. 분류 기준(매체 vs 피사체)을 모델에 '지시'할 수 없음.**

## 3. 실험 B — 생성형 VLM 속성 추출 (Gemma 4 vs Qwen3-VL)

**방법:** 동일 이미지 8건, **동일 프롬프트**(JSON 출력, "매체 기준으로 분류하라"고 명시) → 두 VLM 비교.

- Gemma 4 31B (로컬 vLLM 서버) vs Qwen3-VL-235B (Alibaba DashScope)

**결과 요약:**


| 모델            | 처리 성공 | JSON 파싱 | 평균 지연 | 평균 토큰 | 유형 일치 |
| ------------- | ----- | ------- | ----- | ----- | ----- |
| Gemma 4 31B   | 8/8   | 8/8     | 7.47s | 276   | 6/8   |
| Qwen3-VL-235B | 8/8   | 8/8     | 6.08s | 312   | 6/8   |


**핵심 발견:**

1. **VLM은 매체-기준 분류 문제를 해결.** "매체 기준으로 분류하라"는 지시만으로, CLIP이 틀린 **완도 해조류센터(건물 사진)를 정확히 '사진저작물'로 분류** (근거까지 생성: *"카메라로 촬영된 실제 장소의 정지 이미지"*).
2. **풍부한 한국어 설명 + 키워드 + 객체/색상** 자동 생성.
3. **이미지 내 텍스트 OCR 동시 수행** (포스터의 영화 정보, "2022완도국제해조류박람회", "66th KOREAN FOLK ARTS FESTIVAL" 등).
4. **AI 생성물 탐지** 🎯 — 떡볶이 이미지의 *"This video was created with the help of generative AI"* 문구를 읽고 **두 모델 모두 '영상저작물(AI생성)'로 판단** → 과제의 AI 생성물 탐지 요구사항과 직결.

**모델 간 차이:**


| 항목      | Gemma 4 31B              | Qwen3-VL-235B                  |
| ------- | ------------------------ | ------------------------------ |
| OCR 정확도 | **"WANDO", "66TH" 정확**   | "ANO", "60th" **오독**           |
| 언어 혼입   | 없음 (깨끗한 한국어)             | "테ント"(일본어), "cylindric"(영어) 혼입 |
| 환각      | 없음                       | "드론사진" 키워드 환각(1건)              |
| 구동      | **로컬 (비용 0, 데이터 내부 보관)** | 클라우드 API (건당 과금, 데이터 외부 전송)    |
| 라이선스    | Apache-2.0               | 상용 API                         |


**→ 결론(잠정): Gemma 4 31B = 운영 권장 (비용·보안·OCR 우위), Qwen3-VL = 폴백.**
**※ 현재 Gemma 서버 일시 미가용 → Qwen3-VL을 현 시점 기본 모델로 운용, 자동 폴백 로직 구현.**

## 4. 실험 C — 임베딩 모델 중복검출 성능 (FAISS 역할)

**방법:** CLIP/SigLIP을 **분류기가 아닌 임베딩 모델**로 평가 (중복검출 KPI 89→92% 대응).
이미지 8건 × 근접복제 4종(리사이즈/재압축/크롭/밝기) = 32개 복제 쿼리 → 원본 검색 rank-1 정확도 측정.

**결과:**


| 모델                     | 라이선스       | 차원   | 중복검출 rank-1 | 정답쌍 유사도 | 타품목 유사도 | 분리margin | 임베딩속도 |
| ---------------------- | ---------- | ---- | ----------- | ------- | ------- | -------- | ----- |
| **SigLIP 2** (so400m)  | Apache-2.0 | 1152 | **100%**    | 0.984   | 0.488   | 0.496    | 0.80s |
| **KoCLIP** (Bingsu)    | MIT        | 768  | **100%**    | 0.981   | 0.450   | 0.531    | 0.54s |
| **multilingual-CLIP**  | Apache-2.0 | 512  | **100%**    | 0.977   | 0.427   | 0.549    | 0.26s |
| **OpenAI CLIP** (L/14) | MIT        | 768  | **100%**    | 0.981   | 0.450   | 0.531    | 0.50s |


전 모델이 4종 변형 전부에서 rank-1 100% (리사이즈/재압축/크롭/밝기 모두 1.0).

**핵심 발견:**

1. **모든 모델이 중복검출에 적합** (정답쌍 ~0.98 vs 타품목 ~0.45로 확실히 분리).
2. **소규모·동일유형 데이터로는 모델 간 변별 불가** → 대규모·다양한 KOGL 데이터로 최종 선정 필요.
3. KoCLIP ≡ OpenAI CLIP (동일 이미지 타워 사용) → 이미지 전용 중복검출에선 동일, KoCLIP은 한국어 텍스트-이미지 매칭 시에만 추가 이점.
4. **변별 후보:** SigLIP 2 = 최신·다국어·최고 차원(정밀); multilingual-CLIP = 최소 차원·최速(인덱싱 비용 우위).

## 5. 종합 결론 — 하이브리드 아키텍처

```
공유저작물 파일
   ├─ 이미지/오디오/영상 → VLM(Gemma/Qwen) ──→ 설명·유형·키워드 (실험 B)
   ├─ 이미지            → SigLIP/CLIP 임베딩 → FAISS → 유사도·중복검출 (실험 C)
   └─ 텍스트/계약서      → OCR + LLM + NER  ──→ 권리정보 (1단계 파이프라인)
                                    └→ 통합 스키마 (20개 요소)
```


| 작업               | 채택 기술                      | 근거                            |
| ---------------- | -------------------------- | ----------------------------- |
| 속성 추출(설명·유형·키워드) | **생성형 VLM** (Gemma/Qwen)   | 매체-기준 분류 가능, 학습 불필요 (실험 A, B) |
| 유사도·중복검출         | **임베딩 + FAISS** (SigLIP 2) | 임베딩 본연의 강점 (실험 C)             |
| 권리정보(텍스트/계약서)    | **OCR+LLM+NER** (기존)       | 1단계 파이프라인                     |


**핵심 메시지:** CLIP을 "분류"에 쓰려던 초기 계획을, 실험으로 검증하여 **"분류는 VLM, 유사도는 CLIP/SigLIP"** 하이브리드로 수정. 각 기술을 본래 강점에 맞게 배치.

## 5.5 추가 실험 — 대규모·다양 데이터 검증 (KOGL 80건/12건)

8건(전부 사진) 한계를 보완하기 위해 KOGL 실제 데이터에서 다양한 유형을 표본추출하여 재검증. **공개 썸네일 URL이 14.4만건 모두 접근 가능함을 확인**(분석 즉시 활용 가능).

### (1) 임베딩 중복검출 — 다양 80건


| 모델                | 차원   | 중복검출 rank-1 | 분리 margin | 임베딩 속도     |
| ----------------- | ---- | ----------- | --------- | ---------- |
| SigLIP 2          | 1152 | 64.7%       | 0.432     | 0.116s     |
| KoCLIP            | 768  | 65.0%       | 0.419     | 0.028s     |
| multilingual-CLIP | 512  | **64.7%**   | **0.438** | **0.015s** |


- 3개 모델 **통계적 동률**(~65%). rank-1이 100%→65%로 낮아진 이유는 모델 약점이 아니라 **KOGL에 동일 이미지가 서로 다른 ID/제목으로 중복 등록**되어 있기 때문(검증: 국립극장 4개 작품 꿈하늘/들오리/말괄량이/팔곡병풍이 **바이트 단위 동일 썸네일**, SHA256 일치). → 이는 과제의 **중복검출/허위등록 방지** 목표와 직결되는 실제 데이터 품질 이슈.
- 정확도 동률이므로 **효율 기준 선정: multilingual-CLIP**(최소 512차원=FAISS 인덱스 최소, 최速). SigLIP 2의 고차원이 정확도 이득으로 이어지지 않음.

### (2) VLM 속성 추출 — 다양 12건 (Qwen3-VL)

- **일러스트 8건(대구 관광지) → 전부 미술저작물 정확 분류** (근거: "선묘 기법", "수채화", "일러스트" 등 기법 정확 인식).
- **사진 4건**: 건물 사진 → 사진저작물 ✓ / 그리고 **KOGL 라벨보다 더 정확한 사례 발견** — 한자 고문헌(가례증해, KOGL=사진) → **어문저작물**, 기하학 문양도(만자의 여러 유형, KOGL=사진) → **도형저작물**.
- **시사점:** ① VLM의 매체-기준 분류가 다양 실데이터에서도 정확 ② **KOGL 정보유형 라벨이 거칠다**(이미지로 저장된 문서·도형을 '사진'으로 표기) → 유형 정답 데이터로는 부적합, work_type은 원본 파일 형식 기준이 타당.

### (3) Gemma vs Qwen 정밀 비교 — 다양 15건 (일러스트·사진·문서스캔·로고)

Gemma 서버 복구 후(Tailscale 영구 연결), 동일 15건에 두 모델 재비교. **15/15 모두 처리, 유형 일치 9/15(60%).** 지연: Gemma 7.44s / Qwen 6.68s, 토큰 ~동일.

- **불일치 6건은 대부분 '오류'가 아님** — 두 패턴:
  - **① 로고 썸네일(3건)**: 보도자료·발표자료집·뉴스 썸네일이 실제로는 **로고**. **Gemma는 일관되게 미술저작물, Qwen은 일관되게 도형저작물** → 로고 유형 분류는 **KOGL이 정할 분류 규약** 문제.
  - **② 텍스트 문서 스캔(3건)**: ICT 보고서·고문헌(가례증해)·신문(제국신문) → **Qwen이 매체를 더 정확히 분류(어문저작물)**, Gemma는 미술/사진으로 과다 분류.
- **상호 보완적 강점:** Gemma = 사진 OCR·한국어 정제 우위 / Qwen = 문서·텍스트 매체 분류 우위.
- ⚠ **주의(검증됨):** 두 모델 모두 **제국신문 창간호를 '독립신문'으로 오인** — 특정 역사 자료에 VLM이 확신을 갖고 오답.
- ⚠ **재확인:** KOGL 썸네일 다수가 작품이 아닌 **로고/대표이미지** → **work_type은 썸네일 분류가 아니라 실제 파일/매체 기준** 으로 판단해야 함.

> 결론: Gemma 운영 권장 유지(OCR·비용·보안), 단 격차 근소·보완적. **유형 항목은 두 모델 통합(consolidation) 고려.** (원본: `reports/vlm_compare_20260608_131551.md`)

## 6. 향후 계획

- **대규모 평가셋 구축** — KOGL 14.4만건(이미지 7.7만, 유형라벨 2.9만)에서 유형별 균형 표본 → Gemma/Qwen 대규모 평가 + 임베딩 모델 최종 선정.
- **유형 분류기 학습** — SigLIP 임베딩 + 경량 분류 헤드 (KOGL 라벨 활용, 공인시험인증 KPI 충족용).
- **파이프라인 통합** — 모달리티 라우터 + 통합 스키마 매핑 + **VLM 자동 폴백**.
- **공인시험인증(KTC/TTA)** — 속성정보 정확도 80→85% 검증 (KOGL 유형별 1,000건).
