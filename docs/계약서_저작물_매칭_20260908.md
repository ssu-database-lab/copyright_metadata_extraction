## 2. How the matching works

**The join key is the numeric ID leading the filename.** `13387752 운수 자판기.pdf` → work `13387752`.

The contract body never prints the work ID. Across all 5,714 non-empty PDFs the ID appears **zero
times**; the only digit runs of 5+ characters are birthdates (8) and fees (6–7). So the filename is
the sole link, and content-based re-derivation of the pairing is impossible.

The *correctness* of each pairing was instead argued from content. Over a 42-contract stratified
sample covering all 14 media × license strata, the PDF body reproduces its index row verbatim:

| field | agreement |
|---|---|
| 제목 (title) | 42/42 sample · 5,708/5,714 full (6 misses are corrupt glyphs, not wrong pairings) |
| license period | 42/42 |
| 권리자 | 5,714/5,714 full population |
| 저작자 · 이용자 · fee · 종별 | all sample rows |

### Work-file selection

1,417 works have more than one candidate file, so the priority is fixed:

1. extension matches the declared media
2. the pipeline can **open** it (`.hwpx/.hwp/.pptx/.zip/.xls*` excluded)
3. the pipeline can **decode** it
4. source rank `gongu_gt > kogl_originals > gongu_fs`
5. otherwise the larger file

This is what moves 126 image works off a `.pptx` onto the `.jpg` sibling beside it
(`work_source=gongu_fs`, `gt_file_swapped=true`). Those 126 must **recompute file size and format
from the file actually staged** rather than copying the 공유마당 record.

> `dataset/{images,videos,documents}` are **not works**. They are 330×230 thumbnails, and 79 files
> in `videos/` are a single Arirang TV logo placeholder copied repeatedly. Excluded outright — had
> they been matched, 51 evaluation sets would have shipped an identical grey image.

### 3.1 The 118 empty contract PDFs — **resolved 2026-09-09**

All 118 were re-rendered from their intact HWPX with Hancom Office 2024 via COM automation.
**117 became eval-ready**; set `101083` stays blocked because its *work* is a placeholder-only KOGL
video — its contract is now fine.

Three causes had to be cleared, and the first two produced actively misleading symptoms:

1. **Wrong CLSID.** The `{965829DB-…}` in `HwpAppModule.dll`'s embedded registration script is *not*
   what Office 2024 registers. `Hwp.exe /regserver` (admin, once) registers
   **`{2291CF00-64A1-4877-A9B4-68CFE89612D6}`**. Hand-written HKCU keys aimed at the DLL's CLSID gave
   `REGDB_E_CLASSNOTREG`, then `CO_E_SERVER_EXEC_FAILURE` — never the real class.
2. **Document security.** Above 낮음, Hancom refuses to fully load HWPX written by a different Hwp
   version and **silently returns a truncated 631-character document** rather than failing; it
   reports `PageCount = 1`. Proven not to be file damage — control contracts whose original PDFs are
   perfect 5-page documents truncate identically. Fix: **문서 보안 설정 → 낮음**.
3. **Default printer.** Hancom needs a printer for page layout; with a *physical network* printer as
   default it blocks on "Waiting for printer connection…". Set the default to **Microsoft Print to
   PDF** for the run, then restore.

**The output differs from the original cohort, and that is recorded rather than hidden.** Hancom 2024
lays these out **landscape / 3 pages** where Hwp 2020 produced **portrait / 5 pages**. Content is
**97.4%** of the HWPX source and **all 14 TTA-scored fields are present in every one**; the ~2.6%
shortfall is the 지급방식/지급시기 payment table, every field of which the spec marks 불가/X and which is
therefore not scored. The manifest carries **`contract_rerendered`** so the cohort can be controlled
for, and `dataset/rerendered_contract_ids.txt` lists the ids.

> Acceptance was changed from "exactly 5 pages" to a **content** test — source-text ratio ≥ 0.80 plus
> all eight key clause markers. The page-count rule would have rejected all 118 valid documents. It
> did earn its place, though: it caught the security-truncation, which is why that first batch was
> discarded instead of imported.

Tooling: `api/module/dataset_builder/tools/convert_118_hwpx.ps1` (32-bit PowerShell; `-Unregister`
removes the HKCU keys, which shadow HKLM in the HKCR merge and must go before `/regserver`).

### 3.2 The 59 missing works — not recoverable

Every one of the 59 was already attempted by `download_originals.py`, and the local
`download_log.json` records why:

| outcome | video | text | meaning |
|---|---:|---:|---|
| `no_in_site_download` | 52 | 0 | KOGL publishes no downloadable original for this work |
| `failed` — 파일을 찾을수 없습니다 | 5 | 2 | link exists, asset missing server-side |

Re-running the downloader will not help; it already tried. Obtaining these requires KOGL to publish
the originals or supply them directly. (An earlier note in this project suggested these were
re-downloadable because the IDs appear in the 144k export — that is wrong. Catalog presence is not
file availability.)

The root cause of the 57 videos: 91 KOGL downloads failed during collection and were substituted
with different IDs, but contract generation drew from the **pre-substitution** list. Video preview
thumbnails were captured before substitution and document previews after, which is why only the
video side silently fell back to a placeholder.

### 3.3 The 40 `.hwp` works — **resolved**

These are 어문 works whose only file is `.hwp`. `universal_ocr.py` lists `.hwp` in
`supported_extensions`, but `_process_hwp` (line 133) is a stub:

```python
def _process_hwp(self, file_path: Path) -> List[str]:
    """Convert HWP to images (placeholder)."""
    logger.warning("HWP to image conversion not implemented yet")
    return []
```

An empty image list means empty OCR, which trips the early-stop guard. So these fail silently today.
Implementing the handler — the venv already has `pyhwp` 0.1b15 (`hwp5html`, `hwp5txt`, `hwp5odt`)
for reading HWP v5 — would recover all 40 and is the cheapest of the three repairs.

### 3.4 The 14 scoring caveats — runnable, but do not score blindly

- **`TITLE_GLYPH_CORRUPT` (6).** The HWPX titles are clean NFC text; the PDF export is where they
  break. The Korean font (한양신명조) has no glyph for precomposed accented Latin, so the exporter
  emitted a CID whose glyph is a hollow rectangle and wrote no usable ToUnicode entry — a reader
  falls back to the raw CID as ASCII (`é`→`:`, `è`→`4`). At 400 dpi a human sees
  `Rose Duchesse de M□dina-C□li` — a tofu box, not a wrong letter.
  **Re-rendering with Hancom will not fix this**, because the defect is font *coverage*, not text:
  `æ`/`œ` (present in KS X 1001) render correctly in sibling contracts from the same batch, while
  `é`/`è`/`É` (absent from KS X 1001) fail in all 6. Set `gt_title_scorable=false` and exclude the
  title attribute for these 6, or score against the rendered form.
- **`MEDIA_RELABELED` (7).** Source-catalog label errors, not processing failures: 6 어문 works are
  `.jpg` scans of sheet music/lyrics, 1 어문 is a genuine 30-second 1080p `.mp4`. The router
  dispatches on extension anyway, so these process correctly; only the `media_declared` label is wrong.
- **`DUP_WORK_CONTENT` (1).** KOGL videos 61120 and 61132 are byte-identical 607.9 MB files
  registered twice under different IDs. Keep one; the second is marked so the two sets are not
  treated as independent evidence.

### Ground-truth pitfalls

- **`meta_copyright_holder_name` (저작권자명) is not ground truth.** It is never printed in the
  contract; the 80% agreement with what *is* printed is coincidental. Use `gt_rights_holder`
  (권리자, printed in 100% of contracts) and `gt_author` (저작자). See §5.
- **`gt_work_kind` is the printed term.** Image works print 종별 as **사진저작물**, so scoring
  against `image`/`이미지` fails all 2,409 image contracts.
- **License cannot be scored from the contract.** All 5,716 non-empty PDFs are the same 5-page
  `저작재산권 이용허락 계약서` template, with **zero** mentions of 공공누리, CC BY, 기증 or 만료.
  라이선스 유형 must be marked tier `제외`, not scored as a failure.
- **`만료-KOGL` (404 rows) exists only in the source index.** KOGL metadata has no license column and
  the ID ranges interleave with plain KOGL, so it cannot be reconstructed. Preserved verbatim in
  `license_bucket_raw`.
- **`document_type` is `저작재산권 이용허락 계약서` for every row.** The source's `양도_*` columns are
  the material-delivery date, not a contract type, and are exposed as `delivery_date`.

## 5. `저작권자명` is a schema gap, not just a data quirk

The contract names three parties, and the source catalog adds a fourth:

| field | role | printed in contract? | distinct values |
|---|---|---|---:|
| 권리자 | the licensor — party to the agreement | **yes, 100%** | 240 |
| 저작자 | the author who created the work | **yes** | 465 |
| 이용자 | the licensee | **yes** | — |
| 저작권자명 | economic-rights owner per the source DB | **no** | 801 |

They agree only in half the corpus: all three identical in 2,952 rows (51%); 권리자 = 저작자 in 71%,
저작자 = 저작권자명 in 68%, 권리자 = 저작권자명 in 63%. (Never all three distinct at once.)

**The TTA standard we proposed already models this correctly** — 권리주체 정보(4) has six
sub-elements: 저작자(4.1) `author`, 저작권자(4.2) `copyright_holder`, 저작재산권자(4.3)
`economic_rights_holder`, 이용허락자(4.4) `licensor`, 공동저작자(4.5) `co_authors`,
권리주체 식별자(4.6) `rights_holder_identifier` — and it maps the contract fields explicitly:
권리자 → `economic_rights_holder, licensor`; 저작권자명 → `copyright_holder`; 저작자 → `author`.

**Our 72-field schema is what is behind.** Four of those six are missing:

| TTA element | field | in our schema? |
|---|---|---|
| 4.1 저작자 | `author` | ❌ |
| 4.2 저작권자 | `copyright_holder` | ✅ |
| 4.3 저작재산권자 | `economic_rights_holder` | ❌ |
| 4.4 이용허락자 | `licensor` | ❌ |
| 4.5 공동저작자 | `co_author` | ✅ |
| 4.6 권리주체 식별자 | `rights_holder_identifier` | ❌ |

And the one field we do have collapses the roles in its own description:
`copyright_holder` = *"저작권자 (저작권 보유자, 권리자, 양수기관 등)"*. The evaluation compounds this by
mapping the ground-truth attribute 저자 → `copyright_holder` (`scoring.py:212`), which is a category
error: under Korean copyright law 저작자 (creator, moral rights) and 저작재산권자 (economic-rights
owner) routinely differ — that divergence is the entire purpose of a 이용허락/양도 contract.

**Recommended fix:** add `author`, `economic_rights_holder`, `licensor` and
`rights_holder_identifier`; narrow `copyright_holder` to 저작권자 alone; and remap the 저자 attribute
in `scoring.py` from `copyright_holder` to `author`. Until then, any rights-holder accuracy figure
mixes three legally distinct roles and cannot be interpreted.

## 6. Notes for ZIP building

- Total work payload is **351 GB**. Only 2,748 rows satisfy the current caps (1.5 MB image/text,
  3 MB video); plan to rsync video to the server rather than uploading ZIPs.
- `make_test_zips.py` **cannot** consume this manifest: it hardcodes one contract (`63155`) at module
  level and inlines that set's ground truth as a literal inside `build_zip()`. A CSV-driven builder
  is needed.
- `/v3` reads `manifest.jsonl` (`api/web/batch_api.py`); required keys are
  `{set_id, work, contract?, media, license_bucket}`. Pipeline routing is decided by **file
  extension**, not by `media` (`api/module/clip_extraction/router.py`).
