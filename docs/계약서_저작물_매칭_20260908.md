## 2. 매칭 방법과 그 근거

**조인 키는 파일명 앞의 숫자 ID** 다. `13387752 운수 자판기.pdf` → 저작물 ID `13387752`.

계약서 본문에는 저작물 ID 가 인쇄되지 않는다. 비어있지 않은 5,714건을 전수 확인했을 때
본문에서 ID 가 발견된 건은 **0건**이며, 5자리 이상 숫자열은 생년월일(8자리)과 이용료(6~7자리)뿐이었다.
따라서 **파일명이 유일한 연결고리**이고, 내용 기반 재검증은 원리적으로 불가능하다.

대신 매칭의 **정당성은 본문으로 검증**했다. 14개 층(저작물형태 × 공유형태)을 모두 덮는
42건 층화표본에서 PDF 본문이 xlsx 행을 그대로 재현했다:

| 항목 | 일치 |
|---|---|
| 제목(제호) | 42/42 (전수 5,708/5,714, 불일치 6건은 악센트 글리프 깨짐) |
| 이용허락 기간 | 42/42 |
| 권리자 | 5,714/5,714 (전수) |
| 저작자·이용자·이용료·종별 | 표본 전건 일치 |

### 저작물 파일 선택 규칙

한 저작물에 후보 파일이 여러 개인 경우(1,417건)가 있어 우선순위를 고정했다:

1. 선언된 미디어와 **확장자**가 일치하는 것
2. 파이프라인이 **여는** 형식 (`.hwpx/.pptx/.zip/.xls*` 제외)
3. 실제 **디코딩되는** 형식 (`.swf/.psd/무확장자` 제외)
4. 출처 순위 `gongu_gt > kogl_originals > gongu_fs`
5. 같은 조건이면 큰 파일

이 규칙 덕분에 원본이 `.pptx` 인 이미지 저작물 126건이 같은 저작물의 `.jpg` 동반 파일로 대체됐다
(`work_source=gongu_fs`, `gt_file_swapped=true`). 해당 126건은 **파일크기·파일포맷 정답을
공유마당 레코드에서 복사하면 안 되고** 실제 담은 파일에서 다시 계산해야 한다.

> ⚠️ `dataset/{images,videos,documents}` 는 저작물이 **아니다**. 330×230 썸네일이며,
> `dataset/videos` 안 79개 파일은 아리랑TV 로고 플레이스홀더 한 장이 그대로 복제된 것이다.
> 저작물 후보에서 완전히 배제했다.

## 3. 결함 200건 — 사유별

| exclude_reason | 건수 | 설명 | 복구 |
|---|---:|---|---|
| `CONTRACT_PDF_EMPTY` | 118 | PDF 가 0바이트. **원본 ZIP 안에서 이미 0바이트** — 추출 실패가 아니라 hwpx→pdf 변환 실패 | `.hwpx` 원본은 76KB로 멀쩡. 재변환 필요 |
| `WORK_PLACEHOLDER_ONLY` | 57 | KOGL 영상. 썸네일만 있고 원본 없음 | KOGL 재수집 필요 |
| `WORK_EXT_UNDECODABLE` | 10 | `.swf`(Flash) 9건, 무확장자 1건 | 디코딩 불가 |
| `MEDIA_MISMATCH` | 8 | 어문인데 `.jpg` 악보/가사 6건, 어문인데 `.mp4` 1건 등 | 개별 판단 |
| `TITLE_GLYPH_CORRUPT` | 6 | `é/è` 가 PDF 텍스트·화면 양쪽에서 깨짐 (`Médina` → `M:dina`) | OCR 이 원복 불가 — 정답에서 제외 권장 |
| `WORK_NO_WORK_FILE` | 2 | 어문 143943·144247 | **복구 불가** — KOGL 서버에서 원본 삭제됨 |
| `DUP_WORK_CONTENT` | 1 | KOGL 영상 61120·61132 가 607.9MB 바이트 동일 | 한 건만 사용 |

*합계가 200을 넘는 것은 한 행이 두 사유를 동시에 갖는 경우가 있기 때문이다.*

### 왜 KOGL 영상 57건이 비었나

KOGL 원본 수집 시 91건이 실패해 **다른 ID 로 대체**됐는데, 계약서 생성은
**대체 이전 목록**을 기준으로 했다. 그래서 계약서는 있는데 원본이 없는 상태가 됐다.
영상 미리보기는 대체 이전에, 문서 미리보기는 대체 이후에 캡처된 탓에
영상 쪽만 조용히 플레이스홀더로 채워졌다.

## 4. CSV 열 안내 (36열)

| 그룹 | 열 |
|---|---|
| 상태 | `set_id` `status` `eval_ready` `exclude_reason` |
| 계약서 | `contract_pdf` `contract_pdf_bytes` `contract_hwpx_in_zip` `document_type` |
| 저작물 | `work_path` `work_arcname` `work_ext` `work_bytes` `work_source` `work_candidate_count` `work_alt_paths` `work_download_status` `media` `media_declared` `fits_zip_cap` `work_content_dup_group` |
| 라이선스 | `license_bucket` `license_bucket_raw` |
| 계약서 정답 | `gt_title` `gt_author` `gt_rights_holder` `gt_licensee` `gt_work_kind` `gt_license_start` `gt_license_end` `delivery_date` |
| 저작물 정답 | `work_title_indexed` `gt_file_size` `gt_digital_format` `gt_file_swapped` `gt_source_record` |
| 참고 | `meta_copyright_holder_name` |

### 정답값으로 쓸 때 주의할 것

- **`meta_copyright_holder_name`(저작권자명)은 정답이 아니다.** 계약서에 인쇄되지 않으며
  전수 5,714건 중 4,574건(80%)만 우연히 일치한다. 권리자 정답은 `gt_rights_holder`(100% 인쇄),
  저작자 정답은 `gt_author` 를 쓴다.
- **`gt_work_kind` 는 종별의 인쇄 표기**다. 이미지 저작물은 계약서에 `사진저작물` 로 인쇄되므로
  `이미지`/`image` 로 채점하면 2,409건이 전부 틀린다.
- **라이선스는 계약서로 채점할 수 없다.** 5,716건 전부 동일한 5쪽짜리
  `저작재산권 이용허락 계약서` 템플릿이고 공공누리·CC BY·기증·만료 표기가 **0건**이다.
- **`만료-KOGL`(404건)은 xlsx 에만 존재한다.** KOGL 메타데이터에는 라이선스 열이 없고
  ID 범위도 일반 KOGL 과 뒤섞여 있어 재구성이 불가능하다. `license_bucket_raw` 로 원형 보존했다.
- `document_type` 은 전 행 `저작재산권 이용허락 계약서` 다. xlsx 의 `양도_*` 열은 계약 종류가
  아니라 **자료 인도일**이므로 `delivery_date` 로 옮겼다.

## 5. ZIP 빌드 시 유의

- 저작물 총량은 **351GB**. `fits_zip_cap`(이미지·어문 1.5MB / 영상 3MB) 을 만족하는 행은 **2,748건**뿐이다.
  영상은 ZIP 업로드 대신 서버로 직접 rsync 하는 경로를 검토해야 한다.
- 기존 `make_test_zips.py` 는 계약서 1건(63155)을 모듈 상수로 하드코딩하고 그 세트의 정답을
  함수 안에 리터럴로 박아 두었기 때문에 **이 매니페스트를 소비할 수 없다.** CSV 를 읽는 새 빌더가 필요하다.
- `/v3` 가 실제로 읽는 것은 `manifest.jsonl` 이다(`api/web/batch_api.py`). 필요한 키는
  `{set_id, work, contract?, media, license_bucket}` 뿐이고, 파이프라인 라우팅은 `media` 가 아니라
  **파일 확장자**로 결정된다(`api/module/clip_extraction/router.py`).
